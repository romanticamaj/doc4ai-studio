# Spike — docling-serve compatible API (compat plan Task 1)

- Date: 2026-10-10 (Windows 11 host, Python 3.12.13 under `uv`)
- Sources read with `gh api` (exact refs below); a scratch venv under `%TEMP%\spike` held `docling-slim 2.137.0`,
  `docling-serve 1.36.0` (`--no-deps` + only the modules its import needed) — deleted after the spike.
- Docker Desktop is installed but its daemon was not running; it was **not** started (the user's machine must not be
  disturbed), so every probe below runs without a container.

### S1 RAGFlow and `json_content: null`

**Source.** `infiniflow/ragflow` tag `v1.0.0-rc1`, `internal/parser/parser/pdf_parser_docling.go` (249 lines) and
`internal/common/http.go`.

**Finding.**
- (a) `parseDoclingStandardResult` collects `document`, `documents[]` and `results[].document|result`, then for each
  document uses **`md_content` first**, else `text_content`, else `json_content["md_content"]`. `json_content` is
  only a third fallback and only for a `md_content` string inside it → `json_content: null` is harmless.
- (b) The chunked attempts (`do_chunking: true`) parse the body as a JSON **array** of chunks or `{"results": [...]}`.
  A docling `ConvertDocumentResponse` object yields zero chunks → "chunked response contained no usable text" →
  RAGFlow moves to the next candidate. Order: `/v1/convert/source` chunked → `/v1alpha/convert/source` chunked →
  `/v1/convert/source` standard → `/v1alpha/convert/source` standard. So against Doc4AI the **third** request is the
  one whose answer is used; the first converts the file (sync wait), the second and third are cache hits (D4 attaches
  to the running task if the first timed out).
- (c) No status check at all: a `status: "failure"` response has `md_content: null` → "standard response contained
  no parsed document" → error. Any HTTP status ≥ 300 → next candidate.
- (d) **New, important:** the request goes through `common.GetSSRFHTTPClient()`, whose `strictSSRFTransport`
  refuses any host that resolves to a private, loopback, link-local, **CGNAT (100.64.0.0/10 — every Tailscale
  address)**, or other non-global IP (`AssertURLSafe`; the only override is a test-only in-memory flag). RAGFlow
  1.0.0-rc1's Docling parser therefore **cannot reach Doc4AI on a LAN or tailnet address**; it needs a globally
  routable URL (Tailscale Funnel or a public reverse proxy — Spec 4's deployment path).
- (e) The same client has `ResponseHeaderTimeout = 20 min` (> our 600 s sync wait); auth header
  `Authorization: Bearer <key>` only when a key is set.

**Decision.** D7 stays: `json_content: null`, `compat.json_content` default `"null"`. No minimal JSON is built
(the `"doc4ai"` value of the setting stays reserved and is accepted by the config, but renders `null` too until a
client needs it). The RAGFlow recipe is graded **B — needs a public URL** (spec §8.2 amended in Task 12/13).
**Affects.** T6 (no JSON builder), T11 shapes (both chunked + standard bodies replayed), T12 `ragflow.md`.

### S2 docling response models: extra keys and enums

**Source.** `docling-project/docling` v2.137.0 `docling/datamodel/service/responses.py`, `base_models.py`,
`tasks.py`; validated with `ConvertDocumentResponse.model_validate()` in the scratch venv.

**Finding.**
- `ConvertDocumentResponse`, `ExportDocumentResponse`, `TaskStatusResponse` have no `extra="forbid"` (pydantic
  default `ignore`): a body with `document.doc4ai` and top-level `doc4ai` validates.
- **But two enums reject the plan's values:** `ErrorItem.component_type` is `DoclingComponentType`
  (`document_backend | model | doc_assembler | user_input | pipeline`, so `"doc4ai"` fails) and
  `ErrorItem.category` is `FailureCategory` (`policy | capacity | source_unavailable | target_unavailable | timeout |
  internal | backend_failure | inference_failure | unknown`, so A2's `"quality"` fails).
- `TaskStatusResponse.task_meta` is `TaskProcessingMeta {num_docs (required), num_processed, num_succeeded,
  num_partially_succeeded, num_failed}` — the spec's `{pages_done, pages_total}` alone fails validation.
  `TaskStatusResponse` also has `failure: PublicFailureInfo | null`; `task_type` is `convert | chunk`.
- `TaskFailureResult = {kind: "TaskFailureResult", failure: PublicFailureInfo}` with
  `PublicFailureInfo = {category: FailureCategory, message, retryable: bool, phase: admission | source_enumeration |
  execution | orchestration, details: {str: str}}` — not the plan's free-form `failure` dict.
- `ConvertDocumentsOptions` (request side) also ignores unknown keys, so `doc4ai_*` extension keys are legal docling
  options.

**Decision.** Extra keys stay where the plan puts them (`document.doc4ai`, top-level `doc4ai`). Enums follow docling:
- errors: `component_type` `"pipeline"` (`"user_input"` for an unsupported/rejected file), `module_name`
  `"doc4ai.<kind>"`, `category` by kind — input/unsupported → `policy`, engine → `backend_failure`, timeout →
  `timeout`, cancelled/other → `internal`/`unknown`; the low-quality note (A2) is `module_name: "doc4ai.quality"`,
  `category: "unknown"`, `error_message: "quality: low (<reasons>)"`.
- `task_meta = {num_docs: 1, num_processed, num_succeeded, num_partially_succeeded, num_failed}` plus the extra keys
  `pages_done`, `pages_total` (allowed, ignored by docling clients).
- failures: `TaskStatusResponse.failure` and `TaskFailureResult.failure` are `PublicFailureInfo` with
  `message = "<error_kind>: <error_msg>"`, `phase: "execution"`, `retryable` true only for timeouts/cancel, and
  `details = {"error_kind", "tried"}` as strings.
**Affects.** T6 models, T8 status/result (plan test `res["failure"]["error_message"]` becomes `["message"]`), T11.

### S3 OpenAPI snapshot

**Finding.** `docling_serve.app.create_app().openapi()` of **docling-serve 1.36.0** (installed `--no-deps` in the
scratch venv; settings at defaults so `/openapi.json` is exactly this document) → `tests/compat/fixtures/
docling_serve_openapi_1_36_0.json` (`info.version = "1.36.0"`, 23 paths, 166 schemas). Schema names present:
`ConvertDocumentResponse`, `TaskStatusResponse`, `ConvertSourcesRequest`, `ConversionStatus` (`pending, started,
failure, success, partial_success, skipped`), `ErrorItem`, `TaskFailureResult`, `PublicFailureInfo`,
`TaskProcessingMeta`, `HealthCheckResponse`. Security scheme `APIKeyAuth` = header `X-Api-Key`. The multipart form of
`/v1/convert/file` has `files` (required) plus every option as its own field. `/v1/result/{task_id}` answers 200 with
`ConvertDocumentResponse | … | TaskFailureResult`. `/v1/status/poll/{task_id}` takes `wait` (query).
**Decision.** The snapshot is generated, not downloaded from a running server (no container runtime running); the
Task 11 test reads only the file.
**Affects.** T11.

### S4 Starlette multipart streaming

**Finding.** Starlette 1.7.0 `Request.form(max_files=1000, max_fields=1000, max_part_size=1 MiB)`: `max_part_size`
caps only non-file fields; file parts go to a `SpooledTemporaryFile` (1 MiB in memory, then a temp file) with **no
total size cap** — a huge upload would be fully written to the temp dir before our code could refuse it.
**Decision.** `compat.jobs.stream_upload` drives `python_multipart.MultipartParser` (0.0.32, already installed) from
`request.stream()`: the single `files` part is written to `UploadManager.part_path(<id>)` with a running byte count
(over `max_file_mb` → stop reading, delete the part, 413); form fields are collected (each ≤ 64 KiB, ≤ 200 fields);
a second file part → 422 `one file per request`.
**Affects.** T7.

### S5 Open WebUI parallelism

**Source.** `open-webui/open-webui` main (v0.11.4, 2026-09-21): `routers/files.py`, `routers/retrieval.py`,
`retrieval/loaders/main.py`.

**Finding.** Each uploaded file is its own `POST /api/v1/files/` whose processing runs as a FastAPI background task
(`process_uploaded_file` → `process_file`); the loader (`DoclingLoader.load`, plain `requests.post`, no timeout)
runs in `run_in_threadpool` — bounded only by anyio's default 40 worker threads. So a batch upload of N files sends
up to N concurrent `/v1/convert/file` requests. The multipart filename is the full server-side path
(`/app/backend/data/uploads/<uuid>_<name>`); `display_name()` reduces it to the base name. Pages: `md_content`
split on `\f`, `page = index` (0-based) **counted before** empty pages are dropped (`if page.strip()`), so empty
segments keep later pages aligned.
**Decision.** Keep `max_concurrent_jobs_per_token = 8`: sync requests over the cap wait for a slot (D3), so a large
batch queues instead of failing; GPU work is serialized by the queue anyway.
**Affects.** T7 (waiting), T12 `open-webui.md`.
